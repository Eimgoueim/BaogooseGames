# Godot 迁移状态

## 开发主线切换

2026-10-03，用户确认迁移成功，并决定后续开发统一使用 Godot。`godot/` 成为当前开发与源码游玩入口；原 HTML、旧发布包及 HTML 打包工具保留作历史参考。以下对照结果和验收边界继续保留，主线切换不意味着尚未执行的人工检查已有通过记录。

## 目标与边界

在 `feat/godot-migration` 分支、当前工作区内把 HTML 游戏迁移到 Godot，保持原版素材、UI结构、文案、数值与内容。原 HTML 不改动，作为行为和视觉对照。发现原版问题先登记，不借迁移修改规则。

## 保留的原版规则问题

- 抽卡界面部分说明写3%，实际代码概率1.5%；原文案与代码分别保留。
- 任意限定宠物出现都会把保底进度清零，因此通常在50抽已清零，100抽大保底分支只在特定导入状态下触发。没有擅自改成新的保底机制。
- 重置后默认信用点60，欢迎奖励标记随默认状态清除；原版欢迎礼包在启动时检查，而非重置动作中发放。保留该时机。
- 地牢结算先写汇总文字、再调用 `rlHUD()`，原界面的汇总会被上一条地牢提示覆盖；迁移保留原版实际显示时机，通关信用点另有原版 toast。

## 验收边界

已迁移主要可达功能不等于已经证明每种组合与所有帧完全一致。固定Canvas像素对照不覆盖整个原生Control界面；原生字体/emoji、CSS模糊/阴影与WebAudio/Godot音频滤波仍有平台实现差异。真实手柄、长时间完整地牢游玩、移动尺寸和全UI视觉需要进一步人工验收。Godot 已成为开发与源码游玩入口；旧 HTML 安装包仅作历史保留，尚未生成新的 Godot 发布包。

`--preview` 不读取/写入玩家原生存档；`--save=绝对路径` 只读预览旧JSON。普通运行保存到 `user://godot-ui/save.json` 并保留备份。浏览器localStorage不会自动同步；导出原JSON再从Godot面板导入。
