# Godot 迁移计划与状态

## 目标与约束

把当前单文件 HTML 游戏逐步迁移到 Godot，只更换底层架构。游戏的 UI、美术、文案、数值与玩法都以当前 `宠物养成游戏.html` 为准，迁移本身不得删减、简化或重新设计内容。逐项迁移时必须对照原版视觉和行为；发现既有 bug 时先保留并登记，修复应作为单独需求处理，避免把迁移和玩法改动混在一起。

在完整功能完成、视觉与行为逐项对照通过之前，不切换主要游戏入口，也不宣称 Godot 版已与原版一致。根 README 的现有游玩说明仍指向原版 HTML。

当前迁移工作在 `feat/godot-migration` 分支和本工作区进行。

## 当前状态：阶段一

阶段一是基础工程和原版视觉验证预览，范围不是完整游戏：

- `godot/project.godot` 建立 Godot 工程；`scripts/parity_viewer.gd` 通过 Godot 原生 `draw_rect` 回放原 HTML Canvas 绘制指令。默认基准为 `theme_sakura`，可用 `-- --fixture=名称` 指定基准，例如 `godot --path godot -- --fixture=night_sakura`。
- `data/catalog.json`、`data/art.json` 和 `data/visual_fixtures.json` 分别保存原配置、像素绘制指令及视觉夹具。当前共 25 个基准：六主题日/夜 12 个、八只宠物，以及家具确认、睡觉、洗澡、佩饰和排泄五个场景。
- `tools/extract_legacy.mjs` 从当前 HTML 确定性提取数据；不依赖 npm。运行 `node tools/extract_legacy.mjs` 会生成/更新文件，`node tools/extract_legacy.mjs --check` 只校验，不更新。
- 存档 codec 保留旧 JSON 的未知字段和墓地碎片；`SaveRepository` 实现原生文件的临时文件与备份机制。它们目前只是基础设施，尚未接入游戏。
- 不自动读取浏览器存档。`-- --save=绝对路径` 只读解析并校验旧 JSON，输出宠物数量；不会据此绘制房间，也不会写回。

F5/F6 展示的是原版 Canvas 静态绘制基准，不包含或验证完整 UI 一致性。原版 DOM 状态栏、头像/宠物槽和浮层面板均未显示。阶段一未迁移 DOM 面板与交互、养成循环、地牢、音频、生死及复活系统；静态家具/佩饰/睡觉/洗澡夹具也不代表这些系统已可操作。存档基础设施同样尚未连入游戏流程。

阶段一可通过以下检查：

```powershell
godot --headless --editor --path godot --quit
godot --headless --path godot --script res://tests/test_saves.gd
godot --headless --path godot --script res://tests/test_catalog.gd
node tools/extract_legacy.mjs --check
```

原生图形环境另运行 `godot --path godot --script res://tests/test_pixels.gd`，以原版绘制指令合成颜色对照 25 个静态场景的 5,621 个采样点（透明混合允许两个色阶舍入差异）。本阶段已通过此检查、存档测试、配置检查及主场景启动检查；没有验证完整 DOM UI 或玩法一致性。

## 后续阶段

- **阶段二：完整界面与输入交互。** 搭建房间布局、全部 DOM 面板的等价界面及键鼠操作；按表逐项验证视觉与交互。
- **阶段三：养成与生死循环。** 迁移宠物状态模拟、互动、道具、经济/成长、离线计算，以及危急、离世、墓地、碎片与复活。
- **阶段四：地牢、音频及剩余系统。** 迁移地牢与手柄、音乐/音效、存档导入导出等未完成模块，并可按依赖拆分子阶段。

阶段顺序允许按依赖调整，但所有清单项都要完成并留有对照验证记录后，才能讨论切换主入口。
