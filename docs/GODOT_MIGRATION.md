# Godot 迁移计划与状态

## 目标与约束

把当前单文件 HTML 游戏逐步迁移到 Godot，只更换底层架构。游戏的 UI、美术、文案、数值与玩法都以当前 `宠物养成游戏.html` 为准，迁移本身不得删减、简化或重新设计内容。逐项迁移时必须对照原版视觉和行为；发现既有 bug 时先保留并登记，修复应作为单独需求处理，避免把迁移和玩法改动混在一起。

根 README 的正式游玩入口仍是原版 HTML。Godot 工程的 `main_scene` 已指向原生迁移预览场景；这不代表切换了产品入口，也不代表 Godot 版已与原版完整一致。

当前迁移工作在 `feat/godot-migration` 分支和本工作区进行。

## 当前状态：阶段二预览

当前批次建立原生房间界面和一部分导航/输入路径，范围是可操作的迁移预览，不是完整游戏：

- `godot/project.godot` 的 `main_scene` 为 `res://scenes/native_room.tscn`。原版静态画布基准仍可单独打开：`godot --path godot --scene res://scenes/parity_viewer.tscn -- --fixture=night_sakura`。
- 原生房间使用动态 `RoomRenderer` 绘制房间与宠物，HUD 使用原生 Control；支持宠物自主移动、拖拽与掉落。支持 HUD、六页面、主题/领养/存档/对话框导航、主题 accent、宠物切换与改名，以及已有佩饰穿戴和家具摆放、拖拽、缩放、收回。
- 商店/抽卡/积分和背包/佩饰/房间使用原版 HTML 文案、配置和动作名。购买、抽卡结算、领养、道具使用、养成、复活、地牢与音频仍只有待迁移的操作意图；结果弹窗和动效也尚未完善。界面字号、emoji、阴影等仍需跨引擎视觉验收，当前不声称逐像素一致。
- `--preview` 不读写原生存档。`--save=绝对路径` 只读导入 JSON 并绘制预览，不写回原文件。普通运行读取/写入 `user://godot-ui/save.json`，保存时保留备份。浏览器 `localStorage` 存档不会自动读取。
- `data/catalog.json`、`data/art.json` 和 `data/visual_fixtures.json` 来自原 HTML。`tools/extract_legacy.mjs --check` 校验提取结果而不更新文件。

阶段二验证命令：

```powershell
godot --headless --editor --path godot --quit
godot --headless --path godot --script res://tests/test_saves.gd
godot --headless --path godot --script res://tests/test_catalog.gd
godot --headless --path godot --script res://tests/test_native_ui.gd
node tools/extract_legacy.mjs --check
```

原生图形环境另运行 `godot --path godot --script res://tests/test_pixels.gd -- --native`，用动态 `RoomRenderer` 对照 25 个夹具/场景的 5,621 个采样点。该检查仅覆盖当前固定尺寸和 `t=0` 静态画面；不验证动画、窗口尺寸变化或完整 UI/玩法一致性。可用 `godot --path godot --script res://tests/render_fixture.gd -- --ui --action=themeopen` 导出原生 UI 到 `godot/.runtime/native_ui.png`；不带 `--ui` 时仍导出 Canvas 基准。

## 后续阶段

- **阶段二后续：界面与输入对照。** 完善全部 DOM 面板与键鼠操作，按表逐项核对跨引擎视觉和行为。
- **阶段三：养成与生死循环。** 迁移宠物状态模拟、互动、道具、经济/成长、离线计算，以及危急、离世、墓地、碎片与复活。
- **阶段四：地牢、音频及剩余系统。** 迁移地牢与手柄、音乐/音效、存档导入导出等未完成模块，并可按依赖拆分子阶段。

阶段顺序允许按依赖调整，但所有清单项都要完成并留有对照验证记录后，才能讨论切换主入口。
